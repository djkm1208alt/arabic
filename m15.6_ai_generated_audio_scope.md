**Parent:** [ROADMAP.md](ROADMAP.md) M13 (native-audio plumbing) and M15.5 (audio-provenance

**Base:** `main`, post batch 20.

## 1. What this is, and the one thing it must never do

Generate Arabic audio with a neural TTS model (run locally, not via any live API call — see §3)
and ship the resulting `.mp3` files as static assets, the same way `icons/` already ships static
binary assets alongside `index.html`. This is **not** a runtime dependency or a runtime fetch —
the files are generated once, at dev time, committed to the repo, and served same-origin, exactly
like the audio files `AUDIO.md`'s existing "go-live" plan already anticipated.

**The one thing this must never do: call it "Recorded."** `AUDIO.md` and the M15.5 honesty
indicator exist specifically so the app never claims audio provenance it doesn't have. AI-generated
speech, however good, is not a human native-speaker recording. Reusing the existing
`RECORDED_AUDIO_MANIFEST` / `RECORDED_AUDIO_ENABLED` pipeline as-is — which is what `AUDIO.md`'s
current "go-live" section literally walks through — would make the "🎙️ Recorded" badge lie. This
milestone's real engineering content is adding a **third, honestly-labeled tier**, not just
dropping files into the existing one.

## 2. Three-tier audio provenance (was two)

| Tier | Badge | What it means | Manifest / flag |
|---|---|---|---|
| Recorded | 🎙️ Recorded | A real human native speaker | `RECORDED_AUDIO_MANIFEST` / `RECORDED_AUDIO_ENABLED` (unchanged, still 0 files) |
| **AI Voice** *(new)* | 🤖 AI Voice | Pre-rendered neural TTS, generated once, quality-reviewed, shipped as a static file — consistent across every device | `AI_VOICE_MANIFEST` / `AI_VOICE_ENABLED` *(new)* |
| Synthesized | 🔈 Synthesized | Live, on-the-fly speech synthesis in the visitor's own browser — quality depends entirely on that device's installed voices | (no manifest — the existing `speakText()` fallback) |

`playArabicAudio()`'s resolution order becomes: explicit `audioUrl` → recorded → AI voice →
live synthesis. `audioSourceKind()` returns one of the three tier names; `buildAudioControl()`
renders whichever badge matches. A learner never has to know or care which tier they're hearing —
the badge is purely an honesty/transparency signal, same as it is today.

## 3. Generation: local, not a runtime or dev-tool API call

Checked before scoping: Hugging Face's current **Inference Providers** router (the modern
partner-hosted API) has no text-to-speech task at all — confirmed directly against
`docs/inference-providers/tasks/index`, which lists chat, images, video, embeddings, and
speech-*to*-text, but no TTS. The obvious default model, `facebook/mms-tts-ara`, is also
**CC-BY-NC 4.0** — non-commercial only, which conflicts with this project's own `ROADMAP.md` M23
(subscriptions/monetisation).

**Model:** `openbmb/VoxCPM2` — Apache-2.0 (genuinely commercial-safe), 2B params, 30 languages
including Arabic, 48 kHz output. Not perfect (no explicit MSA-vs-dialect guarantee in its own card)
— a listening-QA pass (§5) is required before any batch of generated files is trusted, the same
"checked, not assumed" discipline every content batch this session has used.

**Generation runs locally** (the user's own machine, with Python + the `voxcpm` package
(which pulls in `torch`) installed) — not from this dev sandbox (no `torch`/`pip` here), and not via any hosted API (VoxCPM2
isn't deployed by any Inference Provider either). `tools/generate-ai-audio.py` (§6) is the script;
it is a **one-time, offline, dev-time tool**, exactly like `tools/build-audio-manifest.js` is a
dev-time tool — nothing it does touches the shipped runtime, and the shipped app still has zero
runtime dependencies and zero runtime fetches (standing rule 5) once the output files are committed
as static assets.

## 4. Scope of what gets generated — staged, not all 611 at once

`tools/audio-manifest.json` currently lists 667 unique recordings needed (214 Tier 1 + 465 Tier 2,
after aliasing; Tier 3's 77-entry consonant×harakah grid stays TTS by the standing M13 decision).
Generating and reviewing 611 files in one pass is a real quality risk — the same reasoning that's
kept every content batch this session narrow applies here too. `tools/generate-ai-audio.py` supports
`--types` / `--tier` / `--limit` filters so generation can be staged:

1. **Pilot (recommended first run):** the 6 marks + 28 letter names + ~15 representative words +
   3 sentences (~52 files) — deliberately spans every item *type* in the manifest (isolated
   letter-sounds are the riskiest case for a general-purpose TTS model trained on natural speech,
   not phoneme fragments — worth surfacing that risk on a small batch before committing further).
2. **Tier 1 (foundation)** — the remaining letters, syllables, dialogues, sentences.
3. **Tier 2 (vocabulary)** — the 465 word-level targets, the bulk of the work.

Each stage: generate → listen-review (§5) → commit → re-run `build-audio-manifest.js` to confirm
coverage → only then move to the next stage. Partial coverage is fine — `resolveRecordedAudio()`'s
existing per-target fallback design (already true for the "recorded" tier) means an ungenerated
target simply keeps using live synthesis until its file exists.

## 5. Listening-QA gate — non-negotiable before any batch ships

No generated batch gets committed without a human listening pass confirming: neutral MSA register
(no regional-dialect coloring), correct ḥarakāt/case-ending pronunciation (the manifest's vowelled
Arabic is the source of truth, matching `AUDIO.md`'s existing recording spec §"Pronunciation"),
intelligibility, and — for the letter-sound targets specifically — that the model actually produces
an isolated consonant/vowel sound rather than reading the letter's *name* or refusing/mumbling on
an unnatural fragment input. A batch that fails this gate does not ship; affected targets stay on
live synthesis.

## 6. What ships in this milestone vs. what's a follow-up

**This milestone (implemented now, alongside the scope doc):**

- `AI_VOICE_ENABLED` flag + `AI_VOICE_MANIFEST` lookup + `resolveAiVoiceAudio()` in `index.html`,
  mirroring the existing `RECORDED_AUDIO_*` machinery exactly.
- `playArabicAudio()` extended to check the AI-voice tier between recorded and live synthesis.
- `audioSourceKind()` returns `"recorded" | "ai-voice" | "synthesized"`; `buildAudioControl()`
  renders the new "🤖 AI Voice" badge (new CSS class, contrast-checked like every other tag).
- `tools/build-audio-manifest.js` extended to also scan an `audio-ai/` directory (parallel to the
  existing `audio/` for human recordings) and report AI-voice coverage alongside recorded coverage.
- `tools/generate-ai-audio.py` — the local generation script (§7). **Not run by this session** —
  authored carefully against the manifest schema and VoxCPM2's documented usage, but genuinely
  untested here (no local Python/torch in this sandbox) — the user runs it and reports back.
- `AUDIO.md` gains a section documenting the third tier and the staged-generation plan.
- Ships with `AI_VOICE_ENABLED = false` and no `audio-ai/` directory yet, so behavior is
  byte-identical to today until the first real batch lands — the same "ships inert" contract M13
  used for `RECORDED_AUDIO_ENABLED`.

**Follow-up, once the pilot batch is generated and reviewed:**

- Flip `AI_VOICE_ENABLED = true` once real coverage exists.
- Stage-by-stage generation per §4.
- `sw.js` offline caching for `audio-ai/`, mirroring the existing optional step for `audio/`.
- The `ROADMAP.md` audio-coverage line update once coverage is meaningful.

## 7. `tools/generate-ai-audio.py` — design (implemented, unverified locally)

- Reads `tools/audio-manifest.json` (the same authoritative inventory `build-audio-manifest.js`
  already produces) — never a hand-maintained word list.
- Filters by `--tier`, `--types`, `--limit`, or a `--pilot` shortcut for the §4 pilot set.
- Loads `openbmb/VoxCPM2` via `transformers` (downloaded once, cached locally by `huggingface_hub`
  — no HF token required for this public, non-gated model; the "Inference Providers" token created
  earlier this session isn't the right credential for local model downloads anyway and can be
  left unused for this path, or deleted if nothing else ends up using it).
- Synthesizes each target's `arabic` (vowelled) text, resamples 48 kHz → 44.1 kHz, encodes mono
  MP3 ~192 kbps CBR (via `ffmpeg`, which is **not installed in this dev sandbox** — the user's own
  machine needs it; the script fails with a clear message naming the missing dependency rather than
  producing a silently-wrong file), trims leading/trailing silence to ~150 ms — matching
  `AUDIO.md`'s existing recording spec exactly, so a human recording could replace an AI-voice file
  later with zero format drift.
- Writes to `audio-ai/<same path the manifest already specifies under `audio/`>` — e.g.
  `audio-ai/words/sch-06.mp3` — so `build-audio-manifest.js`'s coverage check needs only a second
  base-directory scan, not a new path-resolution scheme.
- Idempotent: skips a target whose output file already exists, so a partial/interrupted run can
  resume; `--force` regenerates.

## 8. Invariants held

- Zero runtime dependency, zero runtime fetch (standing rule 5) — generation is offline/dev-time;
  the shipped app reads static same-origin files exactly like `icons/` today.
- `buildAudioControl()` / `playArabicAudio()` — explicitly protected across M13/M15.5 — extended,
  not replaced; every existing call site and behavior (recorded tier, live-synthesis fallback,
  voice-warning, A/B compare) stays exactly as it is.
- Never labeled "Recorded." The whole point of this milestone is adding a tier that can't be
  confused with human audio.
- `RECORDED_AUDIO_ENABLED`, `RECORDED_AUDIO_MANIFEST`, and the entire human-recording pipeline are
  completely untouched.

## 9. Acceptance criteria

- `npm run qa` and `node tools/a11y-audit.js` clean with `AI_VOICE_ENABLED = false` (behavior
  unchanged) and, once a pilot batch exists, clean again with it `true` and partial coverage.
- The new "🤖 AI Voice" badge passes the same contrast check every other UI text does.
- `tools/build-audio-manifest.js --check` correctly reports AI-voice coverage separately from
  recorded coverage.
- No generated file ships without passing the §5 listening-QA gate.
- `tools/generate-ai-audio.py --pilot` produces files matching `AUDIO.md`'s format spec (confirmed
  by the user locally, since this sandbox can't run it).

## 10. Out of scope

- Any change to the human-recording (`RECORDED_AUDIO_*`) pipeline.
- Generating all 611 targets in one pass — staged per §4.
- Any live/runtime call to Hugging Face or any other API from the shipped app.
- A hosted Inference Endpoint (the paid option declined this session in favor of local generation).
