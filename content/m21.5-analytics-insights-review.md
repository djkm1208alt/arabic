# M21.5 — Analytics & learning insights: implementation review

See [m21.5_analytics_learning_insights_scope.md](../m21.5_analytics_learning_insights_scope.md) for the (revised) scope doc.

## What shipped

A new "📊 Your insights" panel in the Progress view, following M15's "Your skills" panel pattern exactly (one `renderInsightsPanel()` + CSS confined to the shared `.panel-block`/`.cat-progress-list` classes those panels already use):

- **Time-per-strand** (`skillPracticeTime()`) — count and summed `latencyMs` per skill from `progress.interactionLog`.
- **Accuracy trend** (`accuracyTrend()`) — bucketed accuracy % over the capped log, rendered as an inline-SVG bar chart. Returns `null` under an 8-event minimum sample; the panel then shows an honest "not enough data yet" instead of a misleading near-empty chart.
- **Recent activity** (`activityByDay()`) — interactions per calendar day, inline-SVG sparkline, for however many recent days are actually present in the capped log.
- **Focus areas** (`weakestFocusAreas()`) — directly reuses M19's own `reviewQueue("weak")`, no new query logic. Framed as "Focus areas," matching the scope doc's own recommendation to avoid a discouraging tone.
- **Export your data as JSON** — real file download (`Blob` + `URL.createObjectURL` + a synthetic `<a download>`), assembling the current `progress` snapshot plus the *full*, unbounded interaction history from M19.5's IndexedDB store via the new `getAllInteractionEvents()`.

## Why this is narrower than the original scope doc

Re-grounded against the real, merged M19 + this branch's own M19.5 before implementing (the third milestone here to do this, after M15.5 and M20.5). The original plan assumed M19.5 held indexed `reviewState`/`interactionEvents` stores purpose-built for a "weakest-N" query. In reality `reviewState` lives in memory (`progress.reviewState`, a plain object) and M19 already exposes exactly the query needed (`reviewQueue("weak")`) — no new index required. And M19.5's IndexedDB store only supported a per-object query; this milestone added the one new capability actually needed, an all-events query (`getAllInteractionEvents()`), and used it only where an async read is a natural fit — the user-initiated export — not on the panel's render path, which stays fully synchronous like every other Progress-view panel.

## Bug caught before it shipped

The panel's "Focus areas" row-builder originally called `reviewObjectDisplayText()` — a helper that existed in this branch's *first* M19 attempt (dropped during the rebase reconciliation onto the real merged M19). It doesn't exist in the current codebase. Caught by the syntax/behavior check before any Playwright run: `reviewObjectDisplayText ? ... : ...` would have thrown `ReferenceError: reviewObjectDisplayText is not defined` the first time a learner had any weak/forgotten object to show. Fixed by adding a small, self-contained `insightsObjectDisplayText()` (kind-aware: lexeme/letter/mark/syllable each store their Arabic text under a different field) rather than depending on code this milestone doesn't own.

## Verification

All run against the real app via Playwright:

1. **Empty state** — zero interactions → "Practice a few words or lessons to start building your insights," no chart rendered.
2. **Known synthetic data, hand-computed** — seeded 10 events (6 correct / 4 wrong, 2000ms latency each, one skill): `skillPracticeTime()` returned exactly `{count: 10, timeMs: 20000}`; `accuracyTrend()` returned `[100,100,100,0,0]` — matches hand-computation exactly (first 6 correct, last 4 wrong, grouped into 2-event buckets); an `<svg>` chart rendered.
3. **Sparse data** — 1 event → trend section correctly shows "Not enough data yet" instead of a misleading single-bar chart.
4. **Export** — seeded 5 events via the real `emitInteraction()` call (mirroring into both `progress.interactionLog` and M19.5's IndexedDB store), clicked the real export button, captured the real browser download, parsed the downloaded JSON: `exportedAt` present, `progress.interactionLog` had all 5 events, `fullInteractionHistory` (from IndexedDB) also had all 5 with the correct shape.
5. **Full regression**: `tools/qa-harness.js` 31/31, `tools/a11y-audit.js` clean (1248 interactive-control renders, 6516 text-node renders — both up from M19.5's run since the new panel adds a button and text/chart content, all checked).

## Out of scope, confirmed unchanged

No cross-learner telemetry, no other UI surface, no predictive recommendations — the panel is exactly the one new Progress-view section the scope doc committed to.
