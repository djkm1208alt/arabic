# M19.5 — Local learner state: implementation review

See [m19.5_local_learner_state_scope.md](../m19.5_local_learner_state_scope.md) for the (revised) scope doc — read that first for why this milestone shipped a smaller, safer design than originally planned.

## What shipped

- **`safeIdb*` wrappers** (`safeIdbOpen`, `safeIdbPut`, `safeIdbGetAllByIndex`, `safeIdbCount`) — one IndexedDB database (`learnArabicLocalState`), one object store (`interactionEvents`, autoIncrement key, indexed on `objectId` and `ts`). Every wrapper resolves rather than rejects on any failure (unavailable, blocked, quota, private browsing) — matching `safeStorageGet`/`safeStorageSet`'s existing philosophy exactly.
- **`mirrorInteractionToIdb()`**, called from inside `emitInteraction()` — fire-and-forget, never awaited, so `emitInteraction` (called synchronously from click handlers throughout the app) stays synchronous.
- **`getFullInteractionHistory(objectId)`** (async) — every event ever recorded for an object, not just what survives the in-memory 400-event cap. Not wired into any UI yet; a ready-to-use data layer for M21.5.
- **`backfillInteractionEventsToIdb()`** — one-time, versioned (a `localStorage` flag), copies whatever's currently in the capped `interactionLog` into IndexedDB on first load after this milestone.

## Why this is smaller than the original scope doc

The original plan (written before M19 existed in this codebase) was a full storage-engine swap — `progress` itself moving to IndexedDB, becoming async. Once M19 actually merged (via a separate, independently-developed PR chain), it turned out to already solve the "unbounded blob" problem pragmatically: `interactionLog` is a capped 400-event ring buffer with an incremental cursor (`reviewCursor`), so `foldReviewState()` never needs the dropped events. The only real gap left was that events beyond 400 are gone forever. This milestone closes exactly that gap — an unbounded, queryable companion store — without touching `progress`'s synchronous, in-memory, `localStorage`-backed role at all. See §1 of the scope doc for the full reasoning; this is the third milestone in this branch (after M15.5 and M20.5) to adapt its scope once grounded in the real, current code rather than force the original plan.

## Verification

All of the following were run against the real app via Playwright, not just read from the source:

1. **A single `emitInteraction()` call mirrors correctly** — `safeIdbCount("interactionEvents")` went from 0 to 1, and `getFullInteractionHistory()` returned it with the right shape.
2. **Backfill works and is idempotent** — seeded a synthetic 10-event `interactionLog`, ran the backfill, confirmed all 10 rows landed; ran it a second time, confirmed the total row count across the whole store did **not** double (11, not 21 — the 1 was the earlier single-event test still present).
3. **Volume beyond the 400-event cap survives** — wrote 450 events for one object directly (simulating what would happen over time via normal use), confirmed `getFullInteractionHistory()` returns all 450 — proving the actual problem this milestone exists to solve is solved.
4. **Graceful degradation with IndexedDB unavailable** — simulated `window.indexedDB` being absent (private-browsing-style restriction) via `page.addInitScript`; confirmed zero page errors, `getFullInteractionHistory()` returns `[]` rather than throwing, and the rest of the app (navigation, views) is completely unaffected.
5. **Full regression**: `tools/qa-harness.js` 31/31 (unchanged from before this milestone — nothing about the existing M19 system was touched), `tools/a11y-audit.js` clean (no UI shipped by this milestone, so no new surface to check, but the full sweep was still re-run to be sure).

## Out of scope, confirmed unchanged

`emitInteraction`, `foldReviewState`, `reviewQueue`, `mistakes`, `retainedSet`, and every UI consumer of `progress` — grep-verified none of these were touched by this milestone's diff beyond the two-line addition inside `emitInteraction` that calls `mirrorInteractionToIdb`.
