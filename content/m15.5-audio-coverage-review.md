# M15.5 — Audio/pronunciation foundation: coverage review

See [AUDIO.md](../AUDIO.md) for how the audio system works and [m15.5_audio_pronunciation_foundation_scope.md](../m15.5_audio_pronunciation_foundation_scope.md) for this milestone's scope doc.

## What this milestone found, and what it actually built

The scope doc was written assuming `playArabicAudio()` needed to be extended to prefer a manifest-resolved recording over TTS, and that a bounded "first tranche" (M14 letters + M15 A1/A2 vocabulary) needed to be defined and wired up separately from the rest of the app's content.

Neither turned out to be true once this milestone actually opened the code. M13 had already shipped that preference logic in full (`playArabicAudio()` → `resolveRecordedAudio()` → `RECORDED_AUDIO_MANIFEST`), and `tools/build-audio-manifest.js` already auto-generates a manifest covering **every** audio target the app has — not a bounded tranche. As of this milestone: 359 distinct targets (98 Tier 1 foundation + 183 Tier 2 vocabulary + 78 Tier 3 drill grid), 275 of which need a unique recording (6 share one via aliases). `RECORDED_AUDIO_ENABLED = false` and zero files exist under `audio/`, so 100% of that plays via TTS today — see `tools/audio-manifest.md` for the full, always-current, per-item table.

So the "turn on the plumbing for a bounded tranche" framing didn't fit what was actually already built. What was genuinely missing — and what this milestone delivered instead — is the **learner-facing honesty and comparison UI** the plumbing never had a front end for:

1. **`audioSourceKind(text)`** — a small helper mirroring `resolveRecordedAudio()`'s exact resolution, so a UI indicator can never drift from what actually plays.
2. **A "🎙️ Recorded" / "🔈 Synthesized" tag on every `buildAudioControl()`** (the shared Listen/Slower widget used across reading, listening, and pronunciation-practice steps — 4 call sites, one change). Reads "Synthesized" for everything today, honestly, since nothing is recorded yet.
3. **A "🆚 Compare with model" button** in `initRecorder()`, shown once a recording exists, when the caller supplies `referenceText` — wired into the `listen-repeat` lesson step (the one step type that both plays a reference and records the learner). Plays the reference, then the learner's take, back to back. No score, no change to the roadmap's "compare to model" boundary.

## Why no "first tranche" file was added

Since the manifest generator already covers the full content set (not a subset this milestone would need to carve out and commit separately), adding a bounded tranche-id file would have meant either (a) artificially restricting the new indicator/compare UI to a subset of content for no functional reason, or (b) duplicating bookkeeping `tools/build-audio-manifest.js` already does correctly. Neither serves the milestone's actual goal (proving the plumbing end-to-end and being honest about it) better than just turning the UI on everywhere the existing manifest already reaches.

## Coverage today

100% TTS (0 of 275 needed recordings present) — see `tools/audio-manifest.md`'s summary table and per-tier listings for the authoritative, regeneratable numbers. This milestone's UI changes make that state *visible* to a learner for the first time (every Listen control now honestly says "Synthesized") rather than changing the underlying coverage, which — per the scope doc's own §7/§8 — is a content-acquisition and licensing task outside any code milestone's ability to resolve.

## Explicitly out of scope (unchanged from the scope doc)

- Sourcing or licensing real recordings.
- Any pronunciation scoring.
- The vocabulary/quiz-flashcard "🔊" speak buttons and the vocabulary quiz's Arabic-prompt audio — these call `playArabicAudio()` directly rather than through `buildAudioControl()`, and don't currently show the source tag. `buildAudioControl()` is the shared widget used across the actual practice/reading/listening lesson flows where the recorded-vs-synthesized distinction matters most; extending the tag to every ad-hoc speak icon across Vocabulary's flashcard/quiz views is a larger UI-surface change than this milestone's audio-plumbing focus, and is left as follow-up work rather than folded in here.
