# M20.9 — Alphabet articulation diagrams

**Status:** Approved (merged via PR #29) and implemented — see the draft PR wiring this into `index.html`. `tools/qa-harness.js` and `tools/a11y-audit.js` both clean; `npm run content:check` confirms `content/letters.json` untouched. One deviation from §1 below, made during implementation: the overview's 28 letter jump-links render as real HTML buttons below the diagram rather than as text inside the SVG map itself — packing 28 individual glyphs into the small SVG chips could not give each one a genuine 44×44 touch target without either overlapping neighbors or substantially enlarging the whole map, so they moved into a normal, fully keyboard/screen-reader-accessible button list right under it. The photo, the 9-zone map, and the per-letter diagrams themselves are unchanged from what was reviewed.

**Parent:** [ROADMAP.md](ROADMAP.md). Depends on M14 (letter objects) and M15.5/M20.5 (audio foundation, `buildAudioControl()`). Sits next to the Alphabet view's existing 🔊 button, does not change it.

## 1. What this is

Wires the already-reviewed articulation illustration set — one head/vocal-tract diagram per letter, showing where and how each of the 28 letters is actually produced, plus a navigation overview grouping all 28 by place of articulation — into the real Alphabet detail view (`selectLetter()` in `index.html`), where the 🔊 button already lives.

The content itself is **not new work**: it went through a full phonetics audit (place/manner/voicing verified per letter against MSA, corrections applied: ق uvular not velar, و's dual gesture, ح/ع genuinely distinguished not just paired, ا separated from ء, ج's regional-variation caveat) and three rounds of visual revision (legibility, a real reference-image comparison, gradient/depth shading), all live at the reviewed artifact. This milestone is the "put it in the app" step, not a content-design step.

## 2. Why this needed its own milestone, not a quick patch

- It's a genuinely new UI surface (a diagram per letter + a new overview view), not a copy edit.
- The existing `buildAudioControl()`/`playArabicAudio()` system is explicitly protected elsewhere in the roadmap (M13/M15.5) — this milestone must sit *next to* it, never modify its behavior.
- 28 diagrams is real content weight; it deserves the same QA pass (`qa-harness`, `a11y-audit`, byte-compare where relevant) as any other content milestone.

## 3. Architectural decision: where the diagram data lives

**Decision: hand-authored directly in `index.html`, not round-tripped through `content/letters.json` + `build-content.js`.**

Reasoning: every other `content/*.json` table is either raw linguistic data (lexemes, letters, marks) or machine-checkable structure (curriculum, roots). The diagrams are neither — they're bespoke SVG paths, hand-tuned coordinate-by-coordinate against real screenshots (documented in this session: the ʿayn head shape alone took three iterations to stop looking anatomically wrong). Forcing that through a JSON schema would mean either flattening rich SVG path data into JSON strings (no real validation benefit, `--lint` can't meaningfully check a bezier curve) or building a generator that doesn't generate anything — machinery with no payoff. Precedent exists for this: `RECORDED_AUDIO_MANIFEST` and `arabicAlphabet` itself are already large lookup tables living directly in `index.html`.

Concretely: a new `ARTICULATION` lookup object (keyed by the same `let:xxx` ids `arabicAlphabet` already uses) plus the `POSTURE`/`HEAD`/render-helper functions from the reviewed artifact, ported in as-is (they're already vetted, no rewrite).

## 4. What ships

1. **Per-letter diagram** — inside `selectLetter()`'s existing detail view, a new collapsible section ("🗣️ How it's made") below the forms table, containing that letter's diagram + caption. Collapsed by default on first render (keeps the existing view's height sane — it already has a forms table, a connects-note, an example word, and a practice-writing button); a learner opts in.
2. **New overview view** — a small addition to the Alphabet tab (not a new top-level nav item): a "Where each sound is made" link/section showing the 9-zone map, each letter a real jump link to that letter's `selectLetter()` entry (re-using `arabicAlphabet`'s existing ids).
3. **Nothing about `buildAudioControl()`, `playArabicAudio()`, or the existing 🔊 button changes.** The diagram is adjacent, informational, not an audio control.

## 5. Invariants — what must NOT change

| Must hold | Why |

## 7. Acceptance criteria

- Every one of the 28 letters shows its diagram, matching the reviewed artifact's content exactly (spot-checked against the artifact, not re-derived).
- Overview's 28 jump-links each land on the correct `selectLetter()` entry in the real app (not just the standalone artifact).
- `tools/qa-harness.js` full regression clean, `tools/a11y-audit.js` clean (new interactive elements: the collapse toggle, the overview's jump links).
- Verified live in the real app via Playwright — not just "the code looks right" — same standard as every other milestone this project has shipped.
- No change to `npm run content:check`'s output (441 objects, same counts) — confirms `content/letters.json` truly untouched.

## 8. Out of scope

- Any change to the diagrams' content/wording (that review already happened).
- Recorded audio for the 6 hard letters (separate, learner-driven, tracked on the `claude/tts-hard-letter-hints` branch).
- A photorealistic/medical-illustration version (discussed and declined this session — different medium, not achievable via hand-SVG).
- Tajwīd/traditional-makhraj secondary labels (mentioned as a possible future enhancement during the phonetics audit, not committed here).
