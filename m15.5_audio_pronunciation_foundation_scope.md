# M15.5 — Audio/Pronunciation Foundation

**Status:** Draft for review. Do not begin implementation until this is approved.

**Parent:** Inserted between M15 (Skills · levels · learning graph) and M16 (Curriculum spine) in [ROADMAP.md](ROADMAP.md). Builds directly on M13 (Native-audio prep).

This turns on, for a defined first tranche of content, the audio plumbing M13 shipped inert.

---

## 1. Why it exists

M13 shipped `RECORDED_AUDIO_MANIFEST`, `playArabicAudio()`, and `tools/build-audio-manifest.js` — confirmed present in `index.html` (lines ~4027 and ~4354) — explicitly described in ROADMAP.md as "inert behind a flag." `AUDIO.md` confirms the current real state: **zero recorded audio files exist in the repo.** All 398 audio targets currently resolve through the TTS (`speechSynthesis`) fallback. 320 of those rows (275 unique recordings + 45 aliases) are identified as Tier 1+2 candidates for real native-speaker recordings; the remaining 78 (the consonant×harakah drill grid) are TTS "by decision," not a gap.

The plumbing has sat unused since M13. M15.5 exists to actually exercise it — on a bounded, defined scope (M14's letters + M15's level-tagged core vocabulary) — before M16 builds a much larger curriculum tree on top of a lesson generator (`generateLessonSteps`) that already has `audio-exercise`/`listen-repeat` step types expecting this plumbing to matter.

## 2. What it delivers

No new libraries. Reuses exactly what M13 shipped: `MediaRecorder`/`getUserMedia` (already used since M6 for the recording/playback feature), `speechSynthesis` (existing TTS fallback), `RECORDED_AUDIO_MANIFEST`, `playArabicAudio()`, `tools/build-audio-manifest.js`.

1. **Defined first tranche**: the M14 `LETTERS` set + the subset of M15's skill-tagged vocabulary that's already reliably level-placed (A1/A2 core). Everything outside this tranche continues on TTS exactly as today — no regression to existing behavior for out-of-tranche content.
2. **`playArabicAudio()` extended** to prefer a manifest-resolved real recording over TTS whenever one exists for the requested item, falling back to TTS exactly as it does now when one doesn't.
3. **A visible "🎙️ Recorded" vs. "🔈 Synthesized" indicator** wherever audio is played. This directly matches the roadmap's honesty principle (standing rule 4, extended by analogy from graded skills to audio provenance) — the app has never overclaimed TTS as native audio, and this makes that distinction visible to the learner rather than just true-but-silent.
4. **An A/B "compare with model" toggle** in the existing pronunciation-practice UI (the `audio-exercise`/`listen-repeat` step types and the standalone recording feature), letting a learner play the recorded/synthesized reference audio back-to-back against their own `MediaRecorder` take. This stays strictly inside the roadmap's explicit boundary ("Pronunciation *scoring* → the recorder stays 'compare to model'; no score") — no scoring is added, only an easier way to do the comparison the app already supports.
5. **`content/m15.5-audio-coverage-review.md`** — a coverage report: how many of the tranche's items actually resolved to a real recording vs. fell through to TTS, generated by `tools/build-audio-manifest.js`.

**Explicit non-code dependency flagged up front:** the actual recorded audio *assets* — real native-speaker recordings — are a content/licensing acquisition task, not something this milestone's engineering work can supply on its own. See §7 and §8.

## 3. Invariants — what must NOT change

| Must hold | Why |
|---|---|
| Every item outside the defined tranche keeps working exactly as today (TTS fallback) | No regression to the 78 out-of-scope items or any content not yet in the tranche |
| No pronunciation *scoring* is introduced | Explicit roadmap deferral (standing rule 4 / "Explicitly deferred" list) |
| `RECORDED_AUDIO_MANIFEST`'s existing shape/resolver contract from M13 is extended, not replaced | Don't destabilize working M13 plumbing |
| Zero new runtime dependencies | Standing rule 5 |

## 4. Migration requirements

None to `progress`. If the "compare with model" toggle needs to remember a learner's preference (e.g. last-used playback speed), that's a small additive `progress` field following the same `safeStorageGet`/`safeStorageSet` pattern as everything else — trivial, additive, no migration function needed since it's a new optional field with a safe default (matching how `dailyGoal` and similar fields were introduced).

## 5. Acceptance criteria

- Every item in the defined tranche either resolves to a real recording or is honestly labeled "Synthesized" — never silently misrepresented.
- `content/m15.5-audio-coverage-review.md` accurately reflects real coverage (spot-checked against the manifest).
- The A/B toggle works for at least one full walkthrough of an `audio-exercise` and a `listen-repeat` step.
- No existing audio playback path (out-of-tranche or in-tranche) regresses — verified via M14.5's `qa-harness.js` if that milestone has landed by this point, or the equivalent manual walk-through otherwise.

## 6. Regression re-tests

Full lesson walk-through for every step type touching audio (`audio-exercise`, `listen-repeat`, plus the standalone pronunciation-recording feature from M6), both themes, `MediaRecorder`-unavailable fallback path (already-established resilience pattern) unaffected.

## 7. Out of scope

- **Sourcing and licensing the actual recordings** — this is a content-acquisition task with legal/licensing dimensions no code milestone can resolve; flagged as a parallel dependency (see §8), not silently assumed.
- Pronunciation *scoring* of any kind — **explicitly deferred**, permanently, per ROADMAP.md.
- Expanding the tranche beyond M14 letters + M15 A1/A2 core vocabulary — later tranches (covering M16's fuller curriculum, and eventually M20/M21's content) are follow-on work once this milestone proves the plumbing end-to-end on a bounded set.

## 8. Open questions

- Who/what sources the actual recordings, and under what license? **Recommend:** treat as a separate, parallel, non-code task (matching how the roadmap already separates "Dialect content → not until commissioned" as a similar external dependency); this milestone's engineering deliverables (§2) are fully buildable and testable using TTS-only placeholders in the manifest, proving the mechanism works, so the milestone doesn't need to block on audio acquisition timing.
- Does the honesty-indicator UI (🎙️ vs 🔈) belong in the M14.1 UI-baseline audit's scope, since it's a new small piece of UI? **Recommend:** no — M14.1 audits and hardens *existing* UI; this is new UI introduced by this milestone, so it ships here, but should follow whatever token/spacing conventions M14.1's `UI_BASELINE.md` documents if M14.1 has landed first.

## 9. Rollout

1. Branch from current `main`.
2. Define the exact tranche id list (M14 `LETTERS` + M15 A1/A2-tagged vocabulary) and commit it as a small manifest-input file.
3. Extend `playArabicAudio()` to check for a manifest-resolved recording before falling back to TTS; verify fallback behavior is unchanged for non-tranche items.
4. Add the recorded/synthesized indicator UI.
5. Add the A/B compare toggle to the existing pronunciation-practice UI.
6. Run `tools/build-audio-manifest.js` against the tranche (with placeholder/TTS-only entries until real recordings exist) and generate `content/m15.5-audio-coverage-review.md`.
7. Full regression walk (§6).
8. Open a draft PR.
9. Merge on your explicit approval.
