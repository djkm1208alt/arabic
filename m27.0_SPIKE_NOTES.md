## What the spike confirmed about the design

1. **The scope's item shape works as written.** `sentence` / `tokens` / `roleOptions` /
   `caseOptions` / `key` map cleanly onto a generator + a renderer; nothing in §2.1 needed to
   change.
2. **`score` as a pure function on the registry entry is worth keeping** (scope §2.1 only implies
   it via the M18 `score?` contract). The renderer calls `exerciseTypes.parse.score(item,
   answers)` and so can a review-mode harness — no logic duplicated in the UI.
3. **Per-annotation `obj` (resolved Q6) flows straight through** to `objectResults` with a
   text-id fallback — one line in `score`.
4. **`marker` as feedback-only (resolved Q4) is the right call** — the picker has two chip groups
   already; a third for `marker` would crowd the mobile layout badly. Confirmed by eyeballing the
   overlay at narrow width.

## Open design questions the spike surfaced (feed back into the scope doc)

- **Token = whitespace split.** `exGenParse` and the renderer both split `sentence` on `/\s+/` and
  index by position. Fine for v1 `sentence` texts, but it assumes the annotation's `w` index and a
  naïve space-split agree. `texts.json` already carries a structured `words[]` — the real generator
  should index tokens from `words[]` and render from it, not re-split a string. **Recommend the
  scope doc say the generator consumes `words[]` and never string-splits.**
- **Option-set size.** With only 3 sibling fixtures the `roleOptions` set leans on the hard-coded
  foils. Against a real annotated corpus the "sibling texts, same `gr:` objective" rule (§2.3)
  needs those siblings to exist first — i.e. M27.b1 must author several annotated sentences per
  objective in one batch, not one at a time. Worth a sentence in §2.3 / the M27.b1 scope.
- **`mabni` + case picker.** When the answer is `case: "mabni"`, asking the learner to also pick a
  role is fine, but the case chip group currently mixes real cases with `mabni` as a peer. That
  reads oddly ("is 'built' a case?"). A cleaner UI might be a first question "declinable or built?"
  then the case chips only when declinable. **Not** in M27.0's remit but note it for M27.b1's
  lesson-authoring.
- **No `transform` here** — deferred per resolved Q1; nothing in the spike wanted it.
