# M21.5 — Analytics & Learning Insights

**Status:** Draft for review. Do not begin implementation until this is approved.

**Parent:** Inserted after M21 (Content scale-out) in [ROADMAP.md](ROADMAP.md), before M22 (Student accounts / personal state).

A **local-first-only** insights panel on top of M19/M19.5's event and review data. No aggregate/cross-learner telemetry — that half is explicitly deferred to M22+.

---

## 1. Why it exists

ROADMAP.md describes M21 as "the beginning of a continuous content operation, not a task with an end" — it never really finishes. That makes it a poor place to also introduce a learner-facing insights feature, since M21 doesn't have a natural completion point to hang a new UI milestone off of. M21.5 exists as a bounded, shippable slice that draws on whatever content depth M21 has reached so far, using the review/event data M19 defines and M19.5 makes efficiently queryable.

This also gives learners something the app has never had: visibility into their own trajectory (which strands they're strong/weak in, how practice time trends, a streak view) beyond the single per-strand snapshot M15's "Your skills" panel already provides.

## 2. What it delivers

No new libraries — an inline-SVG mini-chart implementation (no charting library dependency), consistent with the buildless rule and with how the rest of the app already renders everything from scratch.

1. **A new Progress-view panel**, following the exact pattern M15's "Your skills" panel established: one `renderXPanel()`-style function plus CSS scoped to that one view, respecting the already-established invariant that new CSS stays confined to the view it belongs to rather than leaking into shared styles.
2. **Time-per-strand** — how practice time has been distributed across the 8 strands M15 defines.
3. **Accuracy trend** — a simple trend view over `InteractionEvent` history (M19), rendered as an inline-SVG line/bar chart.
4. **Weakest-N objects** — surfaces the learning objects currently in `weak`/`forgotten` review state (M19's state machine), giving a learner a concrete "here's what to focus on" list — this is exactly the kind of query M19.5's IndexedDB indexes exist to make fast; a single `localStorage` blob would require scanning the entire event history on every render.
5. **Practice-streak chart** — a visual version of the existing `streak` field, again inline SVG.
6. **"Export your data as JSON"** — a privacy-friendly, fully local, one-click download of the learner's own `progress`/review/event data. No server involved; this is the app handing the learner their own data, not sending it anywhere.

## 3. Invariants — what must NOT change

| Must hold | Why |
|---|---|
| No fabricated numbers — every metric shown is either directly computed from real recorded events, or explicitly labeled "insufficient evidence" the same way `deriveLevel` already handles thin data (M15) | Standing rule 4/5 (honesty about limits), extended from skills to analytics |
| New CSS stays confined to the new panel's view | Established invariant from M15's own panel |
| No new libraries (SVG hand-rendered, not a charting dependency) | Standing rule 5 |
| No data leaves the device | This milestone is local-first only — see §7 |

## 4. Migration requirements

None beyond what M19.5 already handles. M21.5 only *reads* the `interactionEvents`/`reviewState` stores M19.5 establishes; it introduces no new persisted learner-state fields of its own (the export feature reads and serializes existing state, it doesn't add new state).

## 5. Acceptance criteria

- Every number shown in the panel is traceable to real recorded `InteractionEvent`/`ReviewState` data — verified by seeding a known synthetic event history and confirming the panel's displayed values match a hand-computed expectation.
- A learner with too little history sees an honest "not enough data yet" state for any metric that can't yet be computed meaningfully — never a zero or a fabricated placeholder presented as real.
- "Export your data as JSON" produces a valid, complete JSON snapshot, verified by round-tripping it against the live IndexedDB state.
- Panel renders correctly at all six breakpoints (M14.1's baseline) and passes M14.5's `qa-harness.js` regression walk if that milestone has landed.

## 6. Regression re-tests

Full Progress-view walk (existing M15 skills panel unaffected by the new panel's addition), theme toggle, breakpoint resize, and a synthetic-large-event-history performance check (confirming M19.5's indexes actually keep the weakest-N query fast rather than degrading with data volume).

## 7. Out of scope

- **Any cross-learner aggregate or telemetry** — explicitly and deliberately deferred in full to M22+, since a real backend doesn't exist before M22 ("Backend / accounts / sync → M22. Any earlier is an empty shell." — ROADMAP.md's own "Explicitly deferred" list). M21.5 does not smuggle in even a minimal telemetry pipeline; the entire aggregate half of "analytics" as a general product category is left for whenever M22's backend exists and a real decision about what (if anything) to aggregate can be made deliberately, with consent, rather than as a side effect of this milestone.
- Any UI outside the one new Progress-view panel — no dashboard redesign, no new navigation. That's M24 territory if it ever becomes a bigger surface.
- Predictive or prescriptive recommendations ("you should study X next") — that kind of synthesis is squarely M25+'s job (the AI tutor layer), which explicitly needs exactly this milestone's data (per-strand level, mistake history) to do better than generic advice. M21.5 surfaces the data; M25+ is what reasons over it.

## 8. Open questions

- Should the export feature include raw `InteractionEvent` rows, or only the aggregated view the panel itself computes? **Recommend:** raw rows plus the current `reviewState`/`progressMeta` snapshot — a full export is more useful to a learner who wants to inspect or back up their own data, and it's a strict superset of the aggregated view (nothing extra to compute).
- Does the weakest-N list risk feeling discouraging rather than useful? **Recommend:** frame it explicitly as "focus areas" with neutral language, not a failure list — a product-copy decision to make during implementation, not a blocker to scoping the milestone now.

## 9. Rollout

1. Branch from current `main` (post-M21, or whatever level depth M21 has reached at the time).
2. Write the inline-SVG chart primitives (line/bar, no dependency).
3. Build `renderInsightsPanel()` and its queries against M19.5's IndexedDB stores.
4. Add the "insufficient evidence" honest-fallback states for thin data.
5. Add the JSON export feature.
6. Seed synthetic event history; verify acceptance criteria (§5) against known-expected values.
7. Full regression battery (§6).
8. Open a draft PR.
9. Merge on your explicit approval.
